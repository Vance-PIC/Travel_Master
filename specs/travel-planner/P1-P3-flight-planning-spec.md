# Spec：旅程規劃 P1–P3 航班決策與訂票比價

- 狀態：開發中；UI 已確認，待完成實作與驗收
- 日期：2026-10-29
- 正式入口：`flight-tracker/web/trip_planner.html`（根路由 `/` 與 `/planner`；舊版數據主控台保留於 `/legacy`）
- 原型：`scratch/ui-preview/p1-review.html`、`p2-flight-comparison.html`、`p3-booking-comparison.html`（三階段可互相導覽；示意票價不代表可訂報價）
- 範圍：從保留旅遊選項，到追蹤候選航班（融合雙引擎與歷史爬蟲快照），再比較訂票通路價格與親子選購指南
- 雙 API 原則：P1、P2、P3 航班即時查價均使用 SerpApi 與 Ignav；歷史快照僅作參考，不可取代使用者明確觸發的即時查詢。

## 1. 目標

讓使用者在地點與日期尚未完全確定時先建立草案，透過價格追蹤比較航班，再以指定旅客組成查詢選定航班的訂票通路與整組總價。使用者最後能從通路連結前往訂票。

成功時，使用者能清楚分辨：

- P1 航班搜尋與加入候選（整合 SerpApi 雲端監控快照、本地 SQLite 歷史資料庫與 Ignav 即時查價）
- P2 候選航班的票價趨勢（自動融合歷史快照與手動更新觀測點）與多組比價清單
- P3 依成人數、兒童數與兒童年齡取得通路報價、各大購票管道親子權益比價（官網直營 vs Trip.com vs 易遊網）與訂票入口

## 2. 已確認的產品規則

1. P1 草案保留出發地、可選目的地、去程日期範圍、回程日期範圍及旅客組成。
2. 成人與兒童分開設定；每位兒童需輸入出發日年齡。旅客組成須沿流程帶到 P3。
3. P1 搜尋結果顯示符合草案條件的直航航班組合，所有金額統一換算為新台幣 `TWD`（`NT$`）整數呈現，航班時間格式化為 `HH:MM → HH:MM`，班號具備完整航空公司代碼前綴（如 `CI154`、`IT216`）與繁體中文航空公司名稱。使用者按「加入候選並追蹤」後，系統同時開始該航班組合的價格追蹤。
4. 候選組合以目的地、去程日期與班號、回程日期與班號識別。日期與班號都必須納入身分，避免不同日期的同班號被合併。
5. 移除候選會一併停止其價格追蹤。單獨停止追蹤則保留候選，之後可恢復追蹤。
   P1 草案的出發地、目的地、去回日期或旅客組成變更後，P2 主區只顯示符合目前條件的候選；不符條件的舊候選保留於收合清單並暫停自動追蹤，供使用者查看或明確移除。新候選記錄加入當時的旅客組成，避免不同人數的價格紀錄混用。
6. P2 每組追蹤航班有自己的頁籤；切換頁籤檢視該組價格趨勢與目標價，並自動融合 `travel/nagoya/flights/itinerary_history.csv` 與本地資料庫 `roundtrip_price_snapshots` 之相符歷史觀測點。
7. 使用者可在 P2 將多組候選加入 P3 比價清單，並可從清單移除；加入比價不等於最終決選。P3 同時顯示所有帶入的完整去回程組合，取得各組通路報價後才決定其中一組。返回 P2 增減候選時，保留既有比價清單；移除 P2 候選時也從比價清單移除。
8. P3 依 P1 的成人數、兒童數及每位兒童年齡查詢各訂票通路，同時呈現「各大購票管道實測比價與選購指南」（航空公司官網直營 vs Trip.com vs 易遊網 ezTravel 之親子選位、兒童餐預訂、颱風直簽彈性與台灣統編發票對照）。
9. 使用者從 P3 的通路連結前往完成訂票。本產品不處理付款或代替通路確認訂位。
10. 名古屋飯店監控與 8 日親子行程參考列為下一階段（Phase 2）擴充範圍，不在本階段實作。

## 3. 頁面需求

### 頂部導覽與雙引擎狀態列

- 顯示 `MCP 雙引擎實時連線中` 狀態徽章、最新雲端爬蟲更新時間（CST）與手動重新同步按鈕。
- 顯示 `SerpApi` 剩餘額度（如 `113餘`，即時查詢 `https://serpapi.com/account.json` 並以 `latest.json` 為備援）與 `Ignav` 狀態按鈕，點擊可開啟「🔑 API Token 配額與雙引擎狀態儀表板」彈窗（檢視本月已用／剩餘次數、進度條與重置日）。
- 提供「⏱️ 定時監控設定」按鈕，點擊可開啟「GitHub Actions 雲端定時監控與降價門檻設定」彈窗，支援設定降價提醒門檻（NT$）並提供直達 `nagoya-flight-monitor.yml` 排程頁面連結。
- 提供三段外觀主題切換器（`◉ 系統` / `☀ 淺色` / `◐ 深色`），連動 `html[data-theme]` 與系統偏好，並持久化於 `localStorage`（`roamPlannerTheme`）。所有文字、圖示、邊框、輸入欄位及互動狀態須使用主題語意色票；深色模式下標題與內文不得沿用深色前景色，正文對比至少達 WCAG 2.1 AA 4.5:1，大字至少 3:1。
- 提供 `/legacy` 切換連結以檢視舊版數據主控台。

### P1｜草案與航班搜尋

- **中英文機場智慧搜尋**：出發地與目的地均內建 30 座台灣、日本、韓國與東南亞熱門機場知識庫（`AIRPORTS_DB`），支援繁體中文城市、機場名稱、區域關鍵字（如「桃園」、「名古屋」、「關西」、「九州」、「北海道」）或 3 碼 IATA 代碼即時下拉聯想與失焦自動解析，並結合 Ignav `/api/planner/airports` 遠端查詢。
- 目的地不限於快捷列；使用者可用城市、機場名稱或 IATA 代碼搜尋並新增清單外地點，支援多選與逐項移除。
- **常用目的地一鍵快捷列**：提供 `👑 名古屋 (NGO)`、`大阪 (KIX)`、`東京羽田 (HND)`、`東京成田 (NRT)`、`福岡 (FUK)`、`沖繩 (OKA)`、`熊本 (KMJ)`、`北海道 (CTS)` 快捷按鈕，點擊即可一鍵加入或切換目的地。
- **歷史航點行情參考（預設收合）**：於 P1 頂部以 `<details>` 預設收合方式整合 `/api/phase1` 各航點歷史來回最低票價與食宿交通估算，並支援一鍵載入歷史相符航班。
- 去程與回程分別使用日期範圍；日期和地點未定案前不鎖定為單一選項（預設為資料庫有豐富快照之 `2027-07-10 ~ 2027-07-11` 去程與 `2027-07-17 ~ 2027-07-18` 回程）。
- 旅客控制項分為成人和兒童。兒童人數變動時，逐位顯示年齡選項（12–17 歲按供應商成人級距查詢；未滿 2 歲提示需先確認抱坐或佔位）。
- P1 可選填「機票總預算（TWD）」，金額為全體旅客來回總價，與草案一起儲存。新增候選時將此值複製為該候選的 P2 初始目標價；後續修改 P1 預算不覆寫已加入候選各自的目標價。
- **偏好航空公司篩選器**：支援即時過濾 `全部航空公司`、`中華航空 (CI 首選)`、`星宇航空 (JX)`、`長榮航空 (BR)`、`國泰航空 (CX)` 與 `廉價航空 (虎航/樂桃/酷航/亞航)`。
- **即時市場比價直達工具列**：自動計算並顯示 `X天Y夜` 與 `X大Y小 (共Z人)`，動態更新 `✈️ Google Flights 即時查價 ↗`、`🏨 Google Hotels 即時查價 ↗` 外部深連結與 `📋 複製 MCP 查詢指令` 按鈕。
- **智慧雙引擎即時搜尋（SerpApi + Ignav 並行＋可設定新鮮度快取＋同航空過濾）**：按下「搜尋航班 →」時，`search_draft()` 具備三層省額度與精準配對保護：
  1. **可設定新鮮度的 SQLite 智慧快取（`planner_search_cache`）**：API 與監控設定中的「價格資料新鮮度」預設 24 小時（可設 1–168 小時），套用 P1 搜尋快取、P2 當前報價與 P3 通路報價。期限內可重用快取；逾期須即時查詢，P2 手動「更新價格」一律略過快取。
  2. **同目的地去程合併掃描＋已知回程班表配對（`KNOWN_RETURN_SCHEDULES`）**：同一出發日跨多個回程日僅呼叫 1 次 `market_scan`，且針對日本 8 大熱門航點（`NGO`、`HND`、`NRT`、`KIX`、`FUK`、`OKA`、`KMJ`、`CTS`）之主力傳航與廉航（`CI`、`BR`、`JX`、`CX`、`JL`、`NH`、`IT`、`MM`）優先採用已知直飛回程班表配對，免除額外 `departure_token` 呼叫（將單次搜尋消耗從 15 次大幅降至首次 2～4 次、重查 0 次）。
  3. **僅保留同航空公司來回（`_same_airline`）與行李資訊格式化（`_format_bags`）**：自動排除不同傳統航空混搭之單程拆票天價組合（如 `CX 去 + CI 回`），並將供應商回傳之物件型 `bags` 轉為繁體中文（如 `托運 1 件 · 手提 1 件`）。
- **搜尋結果階層式整理呈現（目的地頁籤 ＋ 同班號合併卡 ＋ 排序／時段篩選列）**：
  1. **頂部目的地切換頁籤（`#dest-tabs`）**：當搜尋超過 1 個目的地時，自動產生各目的地頁籤（顯示該目的地航班組數與最低起價，如 `👑 名古屋 (NGO) 6 組航班 · NT$24,382起`）及 `🌏 全部航點合併` 頁籤，避免不同城市混排。
  2. **排序與起飛時段控制列（`.result-toolbar`）**：支援切換 `🏆 智慧推薦（早去午回＋傳航優先）`、`💰 價格最低優先`、`🛫 去程時間（早→晚）` 三種排序；去程與回程各有一條 00:00–24:00、以 15 分鐘為刻度的雙端時間範圍軸，拖動後即時依兩段出發時間篩選，預設顯示全天。
  3. **同班號合併代表卡（`itineraryGroupCard`）與內嵌日期比價膠囊（`.date-pill`）**：同一組去回班號（如 `CI154 ⇄ CI155`）濃縮為 1 張主卡片，上方顯示航空公司、去回起降時間（`HH:MM → HH:MM`）、時段徽章（`🏆 旅行大師推薦首選`／`🌅 早去午回優選時段`／`🌙 凌晨紅眼班機`）與最低起價；卡片下方並列各組「去回日期膠囊」（顯示 `MM/DD 去 ➔ MM/DD 回 (X天Y夜)`、對應 `TWD` 價格、資料時間與 `🔥 最低價` 標記）。代表卡亦顯示最低價對應的資料時間；標籤區分本次查詢、24 小時快取及歷史觀測，來源未提供時間時明確標示。每顆膠囊支援**雙向即時追蹤操作**：未追蹤時顯示 **`＋ 追蹤此日`**（點擊立即建立候選並啟動 P2 追蹤），已追蹤時變為 **`－ 取消追蹤`** 按鈕（可直接於 P1 一鍵取消，且與 P2「移除候選」狀態雙向即時同步）。
  4. **P1 結果區頂部與底部前往 P2 導引列**：於 P1 結果區右上角（`#p1-candidate-count` ＋ `#to-p2-top-btn`）與最底部（`#to-p2-btn`）同步顯示目前追蹤中的候選組數（`N 組候選追蹤中`）與 **`查看 P2 價格追蹤 →`** 按鈕（有候選時自動啟用）。
- 結果價格清楚標示「每人估算」與「所選旅客總額估算」；不得將按成人單價乘人數推估的總額標成通路實際報價。

### P2｜候選比較與價格追蹤

- 自動追蹤頻率與資料新鮮度分別設定。`planner.tracking_interval_hours` 預設 6 小時，可設 1–168 小時；排程到期即略過快取查詢 SerpApi 與 Ignav，價格仍新鮮也須新增觀測。新鮮度不阻擋排程查價。
- 本機服務每 15 分鐘檢查到期候選，只處理追蹤中的航班。服務關閉期間暫停；重新開啟後補查到期候選，不補造停機期間觀測。
- 「價格資料與追蹤設定」分別提供新鮮度和追蹤頻率；目標價沿用各候選設定。GitHub 雲端監控另列入口，清楚標示不會自動執行或同步本機設定。

- 顯示候選清單；每筆可切換分頁查看價格或移除候選。已停止追蹤的候選可恢復追蹤。
- 追蹤航班以頁籤切換，每個頁籤代表一組完整去回程組合（同時顯示兩段日期與航班號，避免把同一航班不同日期混為一筆）。
- 每組顯示目前航班價格、觀測期間最低價、距目標價差距、使用者目標價設定，以及自動融合 `SerpApi` 雲端爬蟲歷史（`itinerary_history.csv`）、SQLite 來回快照（`roundtrip_price_snapshots`）與即時手動更新的 SVG 價格走勢圖。
- 價格新鮮度由 API 與監控設定統一控制，預設 24 小時，可設 1–168 小時。進入 P2 時檢查追蹤中候選的最新非歷史觀測，逾期或沒有觀測就略過快取即時呼叫 SerpApi 與 Ignav；供應商失敗時保留歷史趨勢並明示更新失敗。背景排程使用獨立追蹤頻率，到期即查價，不依新鮮度跳過。

- 折線圖保留歷次觀測作為趨勢；新鮮度只決定觀測能否標示為「目前有效價格」，不可刪除過期歷史點。過期價格不得冒充現價或用於目標價差距。
- P2 主價格、最低價、目標差距及折線圖只納入與候選旅客組成相符且計價範圍明確的資料；`price_scope=unknown` 或歷史快照僅記錄總人數、無法確認成人／兒童組成時，保留於可展開的「未納入比較」清單。SerpApi 回程若使用班表配對推估，介面須標為參考價，不能宣稱為可訂票的確定總價。
- 每組候選的 P2 目標價可個別修改或清除，不會反向修改 P1 的草案機票總預算。
- 每組頁籤依序顯示航空公司與去回日期／住宿晚數、去回班號與起飛時間、同旅客參考價與最近變動，並顯示有助判斷行程的標籤。頁籤下方先顯示去回航班，再顯示參考價、目標價差及預設展開的價格趨勢。
- 頁籤價格與變動也只使用與目前候選旅客組成相符的可比較觀測點；沒有可比較觀測時明確顯示「尚無同旅客參考價」，不回退到未知範圍的最後報價。
- 每組候選可加入或移出 P3 比價清單。P2 固定摘要列顯示已選組數、日期與航班，至少選一組才能進 P3；候選的追蹤狀態與是否加入 P3 比價為不同狀態。
- 無候選、無追蹤資料、追蹤暫停及資料錯誤皆須有明確狀態與可理解的下一步。

### P3｜訂票通路與整組價格

- SerpApi 整組計價可由訂票回應的 `search_parameters` 明確回傳成人與兒童數、`type=1`、`selected_flights` 精確配對去回兩段，加上 `booking_options[].together.price` 共同確認。不可僅依搜尋請求、單一金額或缺少旅客回覆推定。Ignav 須展開 `booking_options[].links[]` 的通路價格，缺少計價證據仍標為參考。
- 略過本地快取後的 Google Flights 即時請求須傳入 `no_cache=true`，避免將供應商快取回覆時間當成新查價。

- P3 使用候選頁籤切換完整行程，主體優先呈現已確認整組總價與購票連結；P2 參考價縮為含時間的一行。未確認計價範圍的金額收進「其他參考報價」，供應商技術狀態收進「查詢詳情」。
- API 除錯寫入資料庫旁的 logs/api-debug.jsonl，遮蔽敏感欄位與 URL 路徑、參數，採 5 MiB × 5 檔輪替。記錄查詢識別、階段、供應商、耗時、回應與驗證結果。詳見 docs/planner-api-diagnostics.md；不得將日誌發布於 Pages。

- 頁面頂端摘要顯示帶入 P3 的多組候選與同一份 P1 旅客條件。各組並列完整去回日期、班號、時間、住宿晚數及各通路實際報價；P2 參考價與 P3 可訂報價須清楚區隔。P3 可移出單組並返回 P2 增減候選；只有明確按下最終決選時才寫入 `planner_decisions`。
- P3 的通路查價預覽不得先寫入最終決選。查價失敗或供應商未確認家庭總價時顯示原因，不得以 P2 參考價冒充可訂總價。
- P3 頂部摘要標示 P1 成人數、兒童數及年齡；各卡片的 P2 參考價只取同旅客可比較觀測。通路未回傳明確整組旅客總價與可用訂票連結時，決選按鈕不得啟用。
- **各大購票管道實測比價與選購指南**：自動依選定航班之航空公司產生三欄式比價卡片：
  1. **航空公司官網直營（🥇 最推薦首選）**：標註親子免費選相鄰座位、預訂兒童專屬餐點、遇颱風或班機異動直簽免手續費、行李額度與官網直達連結。
  2. **Trip.com（國際 OTA 平台）**：標註促銷折扣、起飛前 48h 選位限制與平台退改機制。
  3. **易遊網 ezTravel（台灣在地旅行社）**：標註可開立台灣統一發票、24h 中文客服與信用卡分期彈性。
- **即時供應商通路報價（Ignav Deep Links）**：對具備即時 `ignav_id` 之候選查詢 `get_booking_links`，列出實際回傳之通路報價、價格範圍與訂票連結。
- **雙 API 即時查價**：使用者按下每組候選的「查詢通路」時，對該組航班即時呼叫 SerpApi 與 Ignav，兩邊都必須略過搜尋快取；不可只呼叫 Ignav，也不可將 P1/P2 或資料庫的舊觀測當成本次 P3 報價。SerpApi 查詢須使用實際去回日期、成人數與兒童年齡級距；Ignav 同時查詢相符票價與 `get_booking_links` 訂票入口。
- **航班精確配對與來源呈現**：兩個 API 的回覆均須依去程日期／班號、回程日期／班號配對目前候選；不得用相近日期、不同班號或僅航線相同的結果代替。P3 分別標明 SerpApi、Ignav 的價格、旅客計價範圍、回覆狀態、查詢時間及訂票連結；沒有價格的來源仍可列出連結，但須明示「未提供價格」。
- **整組總價與決選防護**：只有供應商明確回傳符合本次成人數、兒童數與年齡級距的整組總價，並有可用訂票連結時，該通路才可作為決選依據。若回傳每人價、計價範圍未知、旅客組成不符或無法精確配對，保留為未驗證資料並說明原因；不得推算整組總額，也不得啟用依賴該報價的決選操作。
- 若旅客含未滿 2 歲嬰兒，阻擋未驗證之家庭總價並提示需先確認抱坐或佔位；若候選來自歷史或 SerpApi 快照（無 `ignav_id`），明確提示使用上方各大購票管道直訂，不以假報價替代。

## 4. 旅客與報價資料契約

### 私人部署與追蹤呈現

- 單一使用者使用，新版介面與 API 同源部署於 HTTPS 私人服務；Pages 保留舊入口至新版驗收後才切換。帳密由環境變數提供，保護所有頁面與 API，健康檢查不含私人資料。
- SQLite 與設定使用持久儲存，升級前備份並保留舊映像；單 process 執行背景追蹤。部署操作見 `docs/travel-planner-private-deployment.md`。
- 趨勢圖提供觀測日期、金額軸、目標價虛線與觀測點明細；P2 提供最近查詢及下次預計時間。

P1 至 P3 至少共用下列旅客資料：

```json
{
  "adults": 2,
  "children": [
    { "age_at_departure": 9 },
    { "age_at_departure": 7 }
  ]
}
```

正式 P3 報價結果關聯至通路與完整來回航班，保存供應商名稱、TWD 換算金額、價格範圍（`price_scope`）、稅費／行李／退改條件、報價時間與通路訂票連結，並附上 `channel_comparison` 三大購票管道選購指南。

不得以固定兒童折扣估算正式報價。

## 5. 原型與正式資料界線

原型（`scratch/ui-preview/p1-review.html`）是使用者確認的 P1 版面與互動參考，示意航班及價格僅供 UI 呈現。正式版本（`flight-tracker/web/trip_planner.html` 與 `flight-tracker/src/planner/service.py`）使用真實雙引擎資料（`SerpApi Google Flights` 雲端監控快照 + 本地 SQLite 歷史快照 + `Ignav` 即時 API）與真實官網／OTA 訂票連結，不沿用原型估算冒充實際報價。

## 6. 技術背景與邊界

- 既有 `flight-tracker` 使用 Python 3.10+、FastAPI/Uvicorn、單頁 HTML 與 SQLite；啟動命令為 `cd flight-tracker` 後執行 `python src/main.py gui`。
- **路由配置**：
  - `GET /` 與 `GET /planner`：呈現新版 P1–P3 旅程規劃介面（`flight-tracker/web/trip_planner.html`）。
  - `GET /legacy`：呈現舊版數據主控台（`flight-tracker/web/index.html`），並提供返回新版 P1–P3 入口按鈕。
- **資料表擴充（`flight-tracker/src/db/database.py`）**：
  - `planner_drafts`：儲存 P1 草案條件與旅客年齡 JSON。
  - `planner_candidates`：儲存 P2 追蹤候選航班（以 `draft_id + itinerary_key` 唯一識別）、追蹤狀態（`tracking` / `paused`）與目標價。
  - `planner_price_observations`：儲存候選航班之歷次觀測價格，並在讀取時與既有 `roundtrip_price_snapshots` 及 `travel/nagoya/flights/itinerary_history.csv` 自動融合。
  - `planner_decisions` 與 `planner_booking_quotes`：儲存 P3 最終決選航班與通路報價紀錄。
- **P3 通路預覽**：`POST /api/planner/candidates/{candidate_id}/booking-preview` 可查詢該候選的通路報價並儲存報價快照，但不寫入 `planner_decisions`；只有按「決選這組」才呼叫既有 `decide` 入口。P3 比價清單依草案 ID 儲存在同一瀏覽器的 `localStorage`，保留返回 P2 後的增減操作；跨裝置同步列為後續資料層擴充。
- **匯率換算與格式化（`flight-tracker/src/planner/service.py`）**：
  - 內建 `FX_TO_TWD`（`1 USD = 31.75 TWD` 等），將供應商回傳之非 TWD 報價統一轉為 `TWD` 整數。
  - 內建 `AIRLINE_NAMES_ZH` 與 `AIRLINE_OFFICIAL_URLS`，自動補齊班號航空代碼前綴並轉為繁體中文航空公司名稱與官網直訂連結。

### 測試策略

- 單元測試（`flight-tracker/tests/test_planner.py`）：涵蓋 P1 草案儲存與旅客年齡分級（12–17 歲轉供應商成人、未滿 2 歲嬰兒防護）、中文機場關鍵字搜尋與解析、候選組合日期與班號唯一身分、SQLite 與 SerpApi 歷史快照融合、P2 暫停／恢復／目標價更新、P3 通路決選與購票管道指南、以及 `/` 與 `/legacy` 路由驗證。

| P3-04 | 在 P3 查兩組候選的通路報價，最後決定其中一組 | 每組查價即時呼叫 SerpApi 與 Ignav 並略過快取；以完整去回日期與班號精確配對，分開標示兩來源價格／連結／查詢時間。查價不改變最終決選；僅明確決選且存在已驗證整組總價時更新 `planner_decisions`。 |
| P3-01 | 以成人與兒童混合旅客查價 | 查價請求包含成人數、每位兒童年齡；畫面顯示相同旅客組成。 |
| P3-02 | 檢視各大購票管道比價與即時通路報價 | 顯示航空公司官網直營 vs Trip.com vs 易遊網親子權益對照卡與直達連結；每個候選即時取得 SerpApi 與 Ignav 回覆，分別呈現真實可用報價及來源時間，不得以舊快照填補即時回覆。 |
| P3-03 | 旅客含未滿 2 歲嬰兒或缺少即時識別碼 | 未滿 2 歲時阻擋未驗證家庭總價並顯示原因；無 `ignav_id` 時引導使用各大購票管道直訂。 |
| UI-01 | 頂部配額儀表板、定時監控彈窗與窄螢幕檢視 | 可開啟 SerpApi/Ignav 配額彈窗與 GitHub Actions 定時監控設定；窄螢幕下自動改為單欄呈現。 |
