# Formal executor

`scripts/hotel_executor.py` separates single-run search, Stage evaluation,
operational persistence, and read-only reports. It reuses the existing SearchAPI
client and room-price parser; it never invokes capability verification or an
experiment. Only SEARCHAPI_KEY is required. No flight business logic is copied.

Commands from the repository:

```sh
python scripts/hotel_executor.py run --monitor marunouchi-booked --allow-query
python scripts/hotel_executor.py run --monitor airport-candidate --allow-query
python scripts/hotel_executor.py report --monitor marunouchi-booked
python -m unittest discover -s scripts -p 'test_hotel*.py'
```

query_enabled stays false. `--allow-query` explicitly permits just that manual
invocation. schedule_enabled remains false; there is no scheduled workflow.
The manual **Hotel monitor executor** workflow selects one monitor, runs offline
tests, executes using the repository Secret, commits records to master, and
uploads `hotel-monitor-<GitHub Run ID>`. Dispatch only after the workflow has
been merged and the user authorizes the run. Existing **Hotel API verification**
remains separate and unchanged.

Every attempted search counts toward max_requests_per_run (1–5). No retries.
Additional hotels/pages beyond the budget produce partial, preserving latest
and history. Coverage names the returned hotels, deferred pages, and provider;
it does not claim the whole market. Missing result groups, malformed prices or
detail identity changes produce error. An explicit empty properties array is
a successful empty observation. No baseline or monitoring data is fabricated.

An observation's evidence map contains literal_value, source, observed_at and a
repo_path or safe_url per field. The evaluator consumes only evidenced values.
The SearchAPI mapping records direct hotel ID, room name and price fields;
query dates/party are context, not occupancy evidence. Currency remains query
currency unless independently evidenced. Physical size/beds/smoking and full
rate policies are unknown when absent. The current Nagoya baseline's unknown
currency/policies prevent comparable results and alerts. A complete evidenced
rate can qualify/equate through the evaluator; a similar name alone cannot.
No external notification delivery is enabled; alert_reached is a stored decision.

Persistence lives at persistence_root/monitor_id:
- latest.json, history.csv and last-run.json follow report-format.md.
- snapshots/run_id.json is immutable evidence; each history row points to its
  observation in that snapshot. No retained rows are appended.
- A prepared `.transaction.json` holds the entire next consistent generation.
  Temporary writes are flushed and individually replaced atomically. If a
  process stops during publication, the next run rolls the prepared generation
  forward under an exclusive lock before making another API request. Report
  detects a pending journal and returns recovery_required without changing files.
- Concurrent local writers fail on `.lock`; workflow runs are serialized. After
  a hard process kill, verify that no writer is alive before manually removing
  its stale lock. Do not delete a transaction journal to bypass recovery.
- API/parse failure before preparation changes only last-run. A prepared
  transaction's recovery completes that successful observation; it is not a
  fabricated retry or a second history append.

Read-only JSON reports return original stored timestamps, config_matches,
last_run and the snapshot. They never query, recover, write or issue new alerts.
When config_matches is false, treat the snapshot as old configuration data.
Full presentation tables can be generated by the Skill from these records
using report-format.md, without querying again.
